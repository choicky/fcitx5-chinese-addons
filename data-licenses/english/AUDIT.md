# English Lexicon Resource Audit (Architecture A §14)

This document records the resource audit required by the Architecture A
Design Instruction §14 for the Fcitx5 Fusion Mixed Chinese-English Input
system. The English Core consumes a single TSV file installed under
`${FCITX_INSTALL_PKGDATADIR}/pinyin/english_lexicon.tsv` at runtime.

## 1. Format

TSV, tab-separated. Lines beginning with `#` are comments; blank lines are
skipped. Each data row is:

```
key <TAB> tier <TAB> display <TAB> flags
```

  * `key` — folded ASCII lowercase lookup form. Only `[a-zA-Z0-9'-]` bytes.
  * `tier` — integer 0..9 source-local frequency bucket.
  * `display` — recommended output spelling (may preserve Title/UPPER case
    for brands and acronyms). Empty means display equals key.
  * `flags` — comma-separated subset of `{p, t, l}` where `p` = proper noun,
    `t` = technical term, `l` = literal-only (accept as typed but excluded
    from completion fan-out). May be empty.

Rows that fail to parse are silently skipped; the loader never aborts, so a
missing or malformed resource cannot break Pinyin initialization (§22).

## 2. Runtime representation

An immutable sorted `std::vector<EnglishLexiconEntry>` keyed by folded ASCII,
binary searched via `std::lower_bound`.

  * Exact / canonical lookup: O(log N).
  * Completion enumeration for a prefix: O(log N + fan-out), fan-out bounded
    per span by `EnglishArcOracle::Config::maxCompletionsPerSpan`.
  * No external dependency (no ICU, no Marisa, no SQLite). Zero runtime cost
    on non-mixed fast paths.

Design rationale: keep the English Core self-contained so it does not couple
to Android prebuilts that would otherwise constrain the Chinese pipeline, and
to avoid adding a new runtime dependency (AGENTS.md "modification boundary").
If profiling later shows the sorted-vector representation to be a bottleneck
at the shipped tier, Marisa-trie is the intended swap-in replacement, since
the Android side already pins it for the Rime plugin
(`fcitx5-android/lib/fcitx5/src/main/cpp/prebuilt/marisa/*`). This has not
been adopted at Batch 3 because there is no evidence the flat representation
is insufficient (see §7).

## 3. Production resource preparation

The shipped `english_lexicon.tsv` in a production build is generated by the
offline script `tools/prepare_english_lexicon.sh` (added in Batch 11 for the
APK pipeline). That script:

  1. Clones the pinned upstream snapshot (`github.com/en-wl/wordlist`,
     tag `rel-2026.02.25`, commit `7e99edab8e32f9f9ea2b15f249ca8d4d67237410`)
     and builds its SQLite database deterministically (`combine.py create-db`).
  2. Extracts American word lists at SCOWL sizes 35/40/50/60 (variant
     level ≤ 1, deaccented), excluding SCOWL's all-uppercase abbreviation,
     uncertain-capital name, trademark and numeric pos-classes (AA, NIH,
     NAACP, MHz, …) — spell-check artifacts that would surface as exact
     arcs for 2–4 letter raw streams overlapping pinyin abbreviations.
     Regular lower-case word classes only; brands/acronyms ship via the
     curated allow-lists. Tiers are assigned from the first size at which
     a word appears via the documented linear map
     `tier = 9 - round(9*(size-35)/25)` (35→9, 40→7, 50→4, 60→0).
  3. Appends this repository's curated `proper.allow` / `technical.allow`
     entries at tier 9, with a deterministic collision rule: a curated
     surface form that differs from its fold only by a leading capital
     never overrides a common SCOWL word; forms with internal or full
     uppercase (iPhone, macOS, GitHub, PDF) always ship canonically.
  4. Emits the final TSV together with its SHA-256, byte size and entry
     count in a JSON manifest at `data-licenses/english/manifest.json`.

The manifest is the single authoritative record of what shipped. **Deviation
from the earlier stance in this document:** the generated production TSV *is*
committed at `im/pinyin/english_lexicon.tsv` so that offline CI runs and the
Android APK build are hermetic (no network fetch at build time). The pin,
commit SHA and full process remain recorded in the manifest, so the same
bytes remain reproducible from the pinned snapshot by rerunning the script.

## 4. Candidate upstream sources considered

The following permissive English corpora were considered. Selection is based
on license compatibility with the LGPL-2.1-or-later Fcitx5 addon, size, and
frequency coverage. None are consumed at compile time; they are inputs to
`tools/prepare_english_lexicon.sh`.

  * **SCOWL v2** (`github.com/en-wl/wordlist`, Kevin Atkinson) — historical
    spell-check word lists maintained as a generator + SQLite catalog;
    permissive custom license whose text explicitly grants the right to
    use, copy, modify, distribute and sell "SCOWLv2, or word lists created
    from it", which covers the derived TSV shipped here. Chosen as the sole
    **word inventory and tiering** source.
  * **`hermitdave/FrequencyWords`** — **rejected** (was previously listed as
    the tiering source in this document — that listing was wrong). Upon
    re-verification the repository licenses its *content* under
    CC-BY-SA-4.0 ("MIT License for code. CC-by-sa-4.0 for content."). Even
    a derived 0..9 tier mapping over that data carries ShareAlike
    obligations incompatible with this LGPL project's redistribution
    stance. Tiering therefore derives exclusively from SCOWL's own size
    tags (§3): a single upstream and a single license for the shipped TSV.
  * **proper-noun and technical-term inventories** are curated as small
    allow-lists maintained by this repository (`proper.allow`,
    `technical.allow`) and reviewed under D-licensed rules; no third-party
    proper-noun dump is shipped in V1 to avoid unverifiable licensing (§6).

Alternative considered and rejected:

  * **WordNet** (Princeton) — its own license has non-commercial clauses on
    derivative works that complicate redistribution inside an LGPL addon.
  * **Wiktionary / wiktextract dumps** — CC-BY-SA is a copyleft viral license
    that would need an attribution chain review; deferred.
  * **dwyl/english-words** — MIT, but provides no frequency evidence and is
    dominated by obscure surface forms that would inflate the completion
    pool; rejected in favor of SCOWL + tiering.
  * **Runtime ISpell sidecar** (existing `SpellEnabled` in
    `im/pinyin/pinyin.cpp`) — rejected as the final Architecture A mixed-input
    data source per §13: the sidecar cannot provide the provenance, tiering,
    and dynamic-confidence signals that UnifiedRanker requires, and depends
    on a provider that is not packaged for Android. The ISpell sidecar is
    preserved as a legacy behavior and not consumed by the English Core.

## 5. Import method and integrity

  * Fixed upstream snapshot: recorded as `<repo>@<tag>` + commit SHA in the
    manifest.
  * Prepared file byte size and SHA-256 recorded in the manifest.
  * The build verifies the manifest before installing `english_lexicon.tsv`;
    a mismatch is a hard build failure.
  * Only the derived tier bucket (integer 0..9) is retained in the shipped
    TSV — no verbatim upstream numeric data.

## 6. Update strategy

  * Manual bump only. The `prepare_english_lexicon.sh` script pins upstream
    by tag/SHA; changing the pin requires a commit-level change review.
  * The manifest is regenerated at every bump, so the shipped bytes are
    always reproducible from the recorded pin.
  * No runtime download, no OTA lexicon updates. Any future update channel
    is a separate Architecture-A change and is out of scope for V1.

## 7. Package size and performance (targets, not measured)

  * Target entry count: 60,000 – 120,000 (SCOWL-derived common English
    inventory + curated proper/technical).
  * Target TSV byte size: ≤ 3 MB uncompressed after tier quantization; no
    compression in the shipped resource (the Android APK container already
    gzips assets).
  * Target lookup latency: p99 < 5 µs for exact; p99 < 50 µs for a full
    prefix completion fan-out on typical mobile raw input lengths (≤ 24
    bytes per arc, `maxArcSpan`). These are design targets; measured numbers
    go into `/tmp/mixed-input-benchmark.md` at Batch 10.
  * Long-tail risk: completion enumeration is a linear scan past
    `lower_bound(prefix)`; on extremely common single-letter prefixes the
    fan-out is large in principle but bounded by `maxCompletionsPerSpan`
    (default 4) per span, so per-tick cost stays bounded. No measurement
    has yet contradicted this bound.

## 8. Repository seed (`im/pinyin/english_lexicon.tsv.example`)

An ~60-line seed file is shipped in the repository as `example`. It is used
by `tools/prepare_english_lexicon.sh` only as a shape/format example for
tests and reviewers; it is not the production resource, and its tier values
are hand-authored by this project's contributors (no external corpus
inheritance). It is not installed to `PKGDATADIR`; the addon loader looks
up `pinyin/english_lexicon.tsv` (non-example) and degrades gracefully if
absent.

## 9. Attribution

The production resource ships alongside the `NOTICE` block generated by the
preparation script, which names the upstream source, tag, commit and license.
It is committed as `data-licenses/english/NOTICE` next to the manifest.

## 10. What is NOT in scope for §14

  * Language-model probabilities or embeddings — Architecture A uses
    frequency-tier evidence, not LM (per §19 cross-source comparability).
  * ISpell fallback — preserved only as the existing legacy behavior at
    `pinyin.cpp` `SpellEnabled`, not consumed by the English Core.
  * Any user-learned English words — those go through the user-lexicon path
    added in Batch 4 and are stored separately under
    `StandardPathsType::PkgData` "pinyin/mixed_english_user.tsv".
